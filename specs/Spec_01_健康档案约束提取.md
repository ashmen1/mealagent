# Spec_01_健康档案约束提取

## 一句话目标

> 从用户健康档案中提取特殊人群、口味偏好和过敏食材，生成统一的约束结构，供后续功能使用。

## 数据模型

| 字段                | 类型                    | 约束（必填？范围？默认？） |
| ------------------- | ----------------------- | -------------------------- |
| profile_id          | integer                 | 必填，来自用户健康档案ID   |
| special_populations | string[]                | 必填；无特殊人群时为[]     |
| taste_preferences   | object<string, boolean> | 必填；无口味要求时为{}     |
| allergens           | string[]                | 必填；无过敏食材时为[]     |

## 端点 / 接口

| 动作                             | 输入            | 成功返回         | 失败情况（状态码）                                      |
| -------------------------------- | --------------- | ---------------- | ------------------------------------------------------- |
| ProfileConstraintService.extract | 正数数profile_id | 上述统一约束结构 | 400：输入或档案值错误；404：档案不存在；500：数据库查询失败 |

Service内部使用共享SessionFactory查询 `user_profiles`，调用方不传入ORM记录或SQLAlchemy Session。每次提取自动打开和关闭Session，不建立全局Session。

## 边界（每条之后会变成一条测试）

- 特殊人群为“无”或空数组时，输出 special_populations: []。
- 过敏食材为“无”或空数组时，输出 allergens: []。
- 口味偏好为“不管”“忽略”“无”或空数据时，均表示无口味偏好，输出 taste_preferences: {}。
- “甜”输出 is_sweet: true；“不甜”输出 is_sweet: false。
- “咸”输出 is_salty: true；“不咸”输出 is_salty: false。
- “酸甜”等复合口味拆成多个布尔字段。
- 口味偏好只有五种口味（甜、清淡、辣、咸、酸）以及其组合。
- 重复值只保留一次
- “无”与其他值同时出现时失败。
- 同一口味同时出现肯定和否定时失败。
- 出现未配置的特殊人群、口味或过敏食材时失败。
- profile_id不在1到50之间时返回400，且不创建Session。
- profile_id合法但数据库中不存在时返回404。
- Session或档案查询失败时返回500。

## 明确不做（划出范围，防 AI 自由发挥）

- 不处理年龄、性别、身高、体重、BMI、体检指标和健康需求。
- 不展开过敏食材对应的具体食材名称。
- 不调用LLM猜测未知值。
