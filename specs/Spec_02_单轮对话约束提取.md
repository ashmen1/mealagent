# Spec_02_单轮对话约束提取

## 一句话目标

> 通过LangChain调用真实LLM，从一条单轮中文对话中提取整餐约束和各菜品约束，生成可直接用于后续菜品查询的统一结构。

## 数据模型

### 输入

| 字段          | 类型     | 约束（必填？范围？默认？）          |
| ------------- | -------- | ----------------------------------- |
| id            | integer  | 必填，正整数                        |
| turn_count    | integer  | 必填，只能为1                       |
| user_messages | string[] | 必填，长度只能为1，元素为非空字符串 |

### 输出

| 字段                   | 类型                   | 约束（必填？范围？默认？）                             |
| ---------------------- | ---------------------- | ------------------------------------------------------ |
| dialogue_id            | integer                | 必填，等于输入id                                       |
| meal_periods           | string[]               | 必填；只允许下午茶、晚餐、早餐、午餐；无餐次时为[]     |
| diner_count            | integer/null           | 必填；明确人数时为正整数，否则为null                   |
| max_total_time_minutes | integer/null           | 必填；明确最长时间时为正整数分钟，否则为null           |
| available_ingredients  | string[]               | 必填；保存“家里只剩”等可用核心食材限制，无限制时为[] |
| dishes                 | Dish[]                 | 必填，至少一项；每项对应一次菜品查询                   |
| evidence               | object<string, string> | 必填；键为字段路径，值为用户原文片段；无约束时为{}     |

### Dish

| 字段                 | 类型                    | 约束（必填？范围？默认？）                                                  |
| -------------------- | ----------------------- | --------------------------------------------------------------------------- |
| count                | integer/null            | 必填；明确数量时为正整数，否则为null                                        |
| dish_type            | string                  | 必填，只允许菜、汤、主食、小菜、未指定                                      |
| taste_preferences    | object<string, boolean> | 必填；键只允许is_sweet、is_light、is_spicy、is_salty、is_sour；无要求时为{} |
| cuisines             | string[]                | 必填；只允许西餐风味、东北菜、粤菜、川湘菜、江浙菜；无要求时为[]            |
| effects              | string[]                | 必填；只允许助眠、减脂、养胃健胃消食、贫血、哺乳；无要求时为[]              |
| special_populations  | string[]                | 必填；只允许上班族、儿童、老人、更年期；无要求时为[]                        |
| required_ingredients | IngredientRequirement[] | 必填；保存标准食材名、食材类别或已配置概念；无要求时为[]                    |

### IngredientRequirement

| 字段  | 类型   | 约束（必填？范围？默认？）                                                        |
| ----- | ------ | --------------------------------------------------------------------------------- |
| kind  | string | 必填；只允许ingredient、category、concept                                         |
| value | string | 必填；分别命中数据库标准食材名、数据库非空食材类别或当前已配置概念“面”            |

没有明确菜品分类时，`dishes` 返回一项 `count: null`、`dish_type: "未指定"` 的菜品，并将口味、菜系、功效、人群和必需食材直接放入该项。存在多个菜品组时，适用于所有组的限制复制到每个Dish中，不使用共享层或继承规则。

## 端点 / 接口

| 动作                            | 输入         | 成功返回         | 失败情况（状态码）                                                      |
| ------------------------------- | ------------ | ---------------- | ----------------------------------------------------------------------- |
| DialogueConstraintService.extract | 一条单轮对话 | 上述统一约束结构 | 400：输入错误；500：数据库或LLM配置错误；502：LLM结构化输出或业务校验失败；503：LLM服务请求失败 |

Service在应用启动时注入共享SessionFactory和长期复用的LLM约束提取器，调用方只传入单轮对话。LLM约束提取器由LangChain适配器实现，业务接口不暴露Session、Provider、模型或SDK类型。每次提取自动打开和关闭Session，不重新创建LLM提取器。

## 边界（每条之后会变成一条测试）

- id不是正整数、turn_count不为1、user_messages不是长度为1的非空字符串数组时返回400，且不查询数据库、不调用LLM。
- 输入通过校验后，使用一次数据库查询加载全部标准食材名和非空食材类别；Session无效或查询失败时返回500，且不调用LLM。
- LangChain适配器必须调用真实LLM，且每次提取只调用一次；调用时使用与本Spec输出一致的完整结构化输出Schema，并禁止未声明字段。
- Prompt必须包含完整输出Schema、字段允许值、归一规则和现有单轮用例；当前对话放在现有用例之后。
- LangChain结构化输出必须为对象；无法生成结构化结果、结果为空或不符合Schema时返回502。
- 结构化结果仍依次经过精确字段、类型、允许值、数值范围、重复与冲突、食材类型和值、证据子串校验；任一校验失败返回502，不直接信任模型或LangChain的首次解析结果。
- 缺少或无法创建LLM运行配置时返回500，且不发起模型请求。
- LLM认证失败、限流、请求超时、连接失败或Provider服务不可用时返回503。
- 没有提取到餐级约束时返回规定空值；`dishes`仍返回一个全部约束为空的“未指定”菜品。
- 每个非空约束必须在evidence中提供字段路径和连续原文片段；路径无效或原文不匹配时返回502。
- 数组内不允许重复值；同一口味同时出现肯定和否定时返回502。
- 微辣、香辣、麻辣归一为 `is_spicy: true`，不辣归一为 `is_spicy: false`，咸鲜归一为 `is_salty: true`。
- 暖胃、胃口不好、养胃、健胃消食、便秘归一为养胃健胃消食；夜宵归一为晚餐；公司、上班、下班归一为上班族；仪式感归一为西餐风味；清爽、别太抢味归一为 `is_light: true`。
- “面”作为当前已配置概念，在提取结果中保留为 `{"kind": "concept", "value": "面"}`；概念关系由后续Neo4j查询负责。
- `available_ingredients` 只限制核心食材，不要求盐、油、水等辅料也在可用列表中，也不表示列表中的食材必须全部使用。
- 现有14条单轮用例的非空结果依次为：1晚餐；2早餐；3午餐和清淡；4晚餐、2人和养胃健胃消食；5午餐和上班族；6晚餐、30分钟和上班族；7可用番茄、鸡蛋、土豆；8晚餐、1份面类主食和1份清淡小菜；9西餐风味；10晚餐；11晚餐和4人；12四道菜和一份汤；13养胃健胃消食；14四道不辣且适合儿童、老人的菜和一份同条件的汤。
- 暂不支持的描述直接忽略，不因此拒绝整条输入。

## 明确不做（划出范围，防 AI 自由发挥）

- 使用LangChain接入真实LLM，但不在业务代码中固定具体Provider、模型名称或服务地址，也不在业务接口中暴露LangChain或Provider专属类型。
- API Key只从运行环境读取，不进入函数输入、Prompt、日志、测试数据或版本库；Prompt、用户原文和模型原始响应不写入日志。
- LLM请求或结构化输出失败时不重试、不切换模型、不降级为普通文本JSON解析、不使用规则引擎兜底、不静默删除或修改非法字段。
- 不缓存或持久化LLM请求、响应和结构化提取结果。
- 不处理多轮对话、历史约束合并和冲突消解。
- 不实现知识图谱查询、菜单生成、份量换算、营养均衡判断或推荐排序。
- 不在本Spec中展开食材概念或实现Neo4j概念关系。
- 不保存“简单、复杂、适合夏天、热乎、牙口不好”等没有既定映射的自由文本。
- 不允许LLM扩充字段允许值、食材类别或食材概念。
- 不在本Spec中实现 `Ingredient.is_core_ingredient`；该字段是后续查询的前置条件。
