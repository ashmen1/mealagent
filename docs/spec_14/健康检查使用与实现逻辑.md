# 健康检查使用与实现逻辑

更新时间：2026-09-16

## 1. 接口区别

| 路径 | 鉴权 | 是否访问依赖 | 是否调用LLM | 用途 |
|---|---|---|---|---|
| `GET /health/live` | 无 | 否 | 否 | 高频进程存活探测 |
| `GET /health` | Bearer | 是 | 主备模型各一次 | 部署后、评测前的低频完整检查 |

`/health` 会产生真实模型调用，不应配置成秒级轮询。

## 2. 正式启动

项目根目录 `.env` 至少需要：

```dotenv
MEALAGENT_API_TOKEN=<评测访问密钥>
LLM_PROVIDER=openai
LLM_BASE_URL=<主模型接口地址>
LLM_AUTH_TOKEN=<主模型令牌>
LLM_MODEL=<主模型名>
```

备用模型使用 `LLM_PROVIDER_BACKUP`、`LLM_BASE_URL_BACKUP`、`LLM_AUTH_TOKEN_BACKUP`、`LLM_MODEL_BACKUP`。不要提交 `.env` 或真实令牌。

Windows运行：

```powershell
.\start.bat
```

等价命令：

```powershell
uv --cache-dir .uv-cache run --no-dev --env-file .env python -m backend.scripts.serve
```

正式入口会自动执行 `docker compose up -d`、等待 PostgreSQL 与 Neo4j 端口就绪、校验菜谱三方一致性，再启动 `127.0.0.1:8000`。不要直接运行应用工厂。

## 3. 调用方法

存活检查无需Token：

```powershell
curl.exe -i http://127.0.0.1:8000/health/live
```

成功固定返回HTTP 200：

```json
{"status":"ok"}
```

完整健康检查必须携带Token：

```powershell
curl.exe -i -H "Authorization: Bearer <访问密钥>" http://127.0.0.1:8000/health
```

缺失、错误或非Bearer格式返回401。依赖全部正常返回HTTP 200和 `ok`；数据库及业务数据正常且仅一个LLM可用时返回HTTP 200和 `degraded`；关键数据异常或两个LLM均不可用时返回HTTP 503和 `unhealthy`。

响应包含 `checked_at`、`duration_ms`、`available_models` 和 `checks`，并携带 `Cache-Control: no-store`。

## 4. 检查内容

- `postgresql`：连接并执行 `SELECT 1`。
- `postgresql_data`：检查菜谱、食材、菜谱食材关系、菜谱营养、用户档案和DRI目标，验证必填布尔及菜谱搭配字段。
- `neo4j`：调用Driver连接检查。
- `neo4j_data`：检查 Recipe、Ingredient、Concept 节点及 `part_of`、`is_a` 关系和必填属性。
- 启动一致性校验：正式JSON、PostgreSQL和Neo4j的1912道菜名及荤素、冷热、主烹饪方式逐菜一致，否则拒绝启动。
- `llm_primary`、`llm_backup`：分别执行一次最多8 token、30秒超时、不重试的最小真实生成。

失败项只返回固定错误码，不泄露连接地址、上游异常或令牌：

| `error_code` | 含义 |
|---|---|
| `dependency_unavailable` | PostgreSQL或Neo4j无法连接 |
| `data_unavailable` | 必需数据、关系或属性缺失 |
| `llm_unavailable` | LLM认证、限流、超时或返回非法 |
| `configuration_missing` | 主备模型配置不完整 |

## 5. 公网使用

SakuraFrp等内网穿透只转发 `127.0.0.1:8000`。不得转发 PostgreSQL 5432 或 Neo4j 17474/17687。

- 高频监控调用免鉴权的 `/health/live`。
- 人工验收调用带Bearer Token的 `/health`。
- `/health/live` 正常但业务失败时，再调用 `/health` 定位依赖。

## 6. 相关实现

| 文件 | 职责 |
|---|---|
| `backend/scripts/serve.py` | 强制读取Token、启动基础设施并守护HTTP服务 |
| `backend/api/app.py` | 鉴权、健康检查路由及HTTP状态码映射 |
| `backend/application.py` | 创建服务容器并执行启动数据一致性校验 |
| `backend/services/health_check.py` | 并行检查并汇总状态 |
| `backend/infrastructure/health.py` | PostgreSQL、Neo4j、数据和LLM探测 |
